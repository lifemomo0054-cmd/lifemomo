# LOCAL POPULATION LAB

지역 생활인구 분석 웹서비스입니다. 지금은 **경상북도 김천시 3시간 이상 체류 생활인구 합성데이터**를 다룹니다.

> [!WARNING]
> 화면의 모든 수치는 **합성데이터**에서 계산했습니다. 공식통계가 아니며 김천시의 실제 생활인구를 나타내지 않습니다.
> 모든 화면 맨 위에 **‘본 서비스의 현재 데이터는 합성데이터를 기반으로 합니다.’** 문구를 항상 표시합니다.

## 실행

Node.js **20.19 이상 또는 22.12 이상**이 필요합니다. (테스트 도구 vitest는 22.12 이상)

```bash
cd web
npm install
npm run dev        # http://localhost:5173
```

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm run build` | 타입 검사 후 `dist/`에 정적 파일 생성 (어느 경로에 올려도 동작) |
| `npm run preview` | 빌드 결과 미리 보기 |
| `npm run typecheck` | 타입 검사만 |
| `npm test` | 집계 엔진·화면별 분석·지도 연결을 Python 집계표와 대조 |
| `npm run data:boundaries` | 시군구 경계(`public/data/boundaries.json`) 다시 만들기 (아래 ‘지도 경계’) |

## 데이터

- 브라우저는 `public/data/population.json` 하나만 읽습니다(약 1.1MB, gzip 약 170KB).
  원본 80,193행을 그대로 담되, 날짜·거주지·성별·연령대를 번호로 바꾸고 체류인구수는 ×100 정수로 적었습니다.
- 이 파일은 저장소 루트에서 `python scripts/build_web_data.py`로 다시 만듭니다([data/README.md](../data/README.md) 참고).
  `python scripts/validate.py`가 이 파일의 모든 행을 전처리 결과와 대조합니다.
- 필터를 바꿀 때마다 브라우저에서 8만 행을 한 번 훑어 다시 집계합니다(`src/data/engine.ts`).
  미리 만든 집계표를 쓰지 않는 이유는 기간·성별·연령·거주지 조합이 무엇이든 모든 숫자가 서로 맞아야 하기 때문입니다.

## 지도 경계

- `public/data/boundaries.json`(TopoJSON, 약 117KB)은 [vuski/admdongkor](https://github.com/vuski/admdongkor)의 행정동 경계 `ver20260401`을 시군구로 합쳐 단순화한 것입니다.
  데이터 기간(2026년 1~6월)과 행정구역 코드가 맞는 시점이라 255개 시군구 코드·이름이 `data/reference/region_codes.csv`와 모두 일치합니다.
- 경계가 없는 코드는 화성시 상위 코드 `41590` 하나입니다(경계는 2026-02 신설된 4개 구로만 있음). 시군구 보기에서는 지도 밖 값으로 따로 알려 주고, 시 단위 보기에서는 화성시로 합칩니다.
- `npm run data:boundaries`가 원자료를 받아 SHA-256을 확인한 뒤 mapshaper로 변환합니다. 원자료(34MB)는 `.cache/`에만 두고 저장소에 넣지 않습니다.
- **출처 표시(필수)**: 본 경계 데이터는 통계청 통계지리정보서비스(SGIS, https://sgis.kostat.go.kr)에서 공공누리 제1유형으로 개방한 행정동 경계를
  가공한 것이며(가공: vuski/admdongkor), CC BY 4.0으로 배포됩니다. 지도 화면 아래에도 같은 내용을 표시합니다.

## AI

- AI(언어 모델)는 **연결하지 않았습니다**. AI Insight 화면의 요약은 `src/data/insights.ts`의 정해진 규칙으로 계산한 문장입니다.
- 연결할 때는 브라우저가 아닌 서버에서 API 키를 다뤄야 합니다. 화면의 ‘AI에 보낼 요약’(원본 행 없이 현재 조건과 요약만, 첫 줄에 합성데이터 명시)을 질문과 함께 보내는 방식을 전제로 자리를 만들어 두었습니다.

## 계산 규칙

| 지표 | 정의 |
|---|---|
| 총 생활인구 | 조건에 맞는 행의 생활인구(체류인구수) 합계. 날짜별 값을 더한 **연인원**이라 실제 인원이 아님 |
| 일평균 생활인구 | 총 생활인구 ÷ 선택 기간 중 **데이터가 있는 날 수** (5월처럼 비어 있는 날은 빼고 나눔) |
| 주요 연령대 | 10세 단위(0~9세, 10대 … 70대, 80세 이상)로 묶었을 때 합계 1위 |
| 주요 유입지역 | 체류지(김천시) 자체를 뺀 거주 시군구 중 합계 1위 |
| 시간 추이 | 날짜별 합계 + 그날을 포함한 최근 7일(달력 기준) 중 데이터 있는 날의 평균 |
| 요일별 생활인구 | 요일별 합계 ÷ 그 요일의 데이터 있는 날 수 (일평균) |
| 주·월별 일평균 | 구간 합계 ÷ 그 구간에서 데이터 있는 날 수 (주는 월요일 시작) |
| 성비 | 여성 100명당 남성 |
| 중위 연령대 | 생활인구를 나이순으로 쌓았을 때 절반이 되는 원본 연령대 |
| 상위 10곳 집중도 · HHI | 체류지 자체를 뺀 외부 유입 기준. HHI = 각 시군구 비중(%)의 제곱합 (0~10,000) |
| 지도 색 단계 | 0보다 큰 값의 최솟값~최댓값을 로그 눈금으로 7등분 |

- 화면의 숫자와 그래프는 모두 데이터 파일을 필터에 맞춰 집계한 값입니다. 코드에 데이터 값을 적어 두지 않으며,
  안내 문구에 들어가는 숫자(날짜별 행 수 범위, 0이 아닌 최솟값, 상한값, 시군구 수 등)도 파일에서 계산합니다.

- 데이터가 없는 날은 0으로 채우거나 보간하지 않고 "데이터 없음"으로 비워 둡니다.
- 김천시 자체(거주지 = 체류지) 행과 상한값(5,932.84) 행은 합계에 포함하되, 화면 아래 메모에 비중을 함께 적습니다.

## 디자인

- 글꼴: Pretendard(본문·숫자), IBM Plex Mono(영문 라벨·번호). 모두 npm 패키지로 함께 빌드되어 외부 CDN이 필요 없습니다.
- 차트 색: 일변량은 파랑 하나 + 회색(강조 형식), 성별은 파랑·주황, 생애단계는 파랑 단일 색상의 명도 단계,
  히트맵·지도는 파랑 7단계(0에 가까운 가장 옅은 단계만 바탕과 대비가 낮고, 칸마다 값이나 툴팁으로 읽을 수 있음).
  라이트·다크 각각의 바탕색에 대해 색각 이상 구분도·대비를 검증한 값입니다(`src/styles/tokens.css` 상단 주석).

